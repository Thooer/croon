# 先例

设计借鉴或对照过的系统与理论，按设计的部分分节。全部待核验：名称、链接、行为来自网页端 LLM 的搜索报告或记忆，尚未对照原文，只作线索。组织与制度的对照在借鉴组织.md。

借用一个先例之前，先写出它的前提，再与 Croon 的前提对照。比如 ocap 预设各方互不信任、连接在运行中临时建立；actor 预设消息与信箱是原语。前提对不上的部分，表里「与设计的关系」不成立。第三列只指向设计的概念，不复述规则。

## 骨架与系统划分

| 先例 | 观察 | 与设计的关系 |
|---|---|---|
| actor 模型；event sourcing；Git | 各管各的状态、只经消息交互；日志是事实、状态是投影；对象不可变、分支是指针 | 骨架：Value、Instance、Reference |
| Agoric SwingSet；E 语言；Spritely Goblins | vat 由内核为它持有 c-list，重启时重放投递记录；SwingSet 的 marshal 把消息分成 body 与 slots，数据里不放引用，引用随 slots 走；JS 代码里引用是不透明的对象，与数据共用名字；SES 是没有环境权利的 JS 沙箱 | 骨架的先例：自洽，也做得出来；但都不是 LLM 智能体框架。body 与 slots 对应 Value 加附带；不透明的引用对应一套名字、两种值；SES 是 Language 求值器的候选 |
| 微内核 | 内核只管能力与调度，驱动与服务在内核之外 | Kernel 只留由保证推出的，其余是扩展 |
| Hydra 操作系统（Wulf 等） | 机制与策略分离：内核给机制，策略由内核之外决定 | 放置：机制与策略分离 |

## Value 与存储

| 先例 | 观察 | 与设计的关系 |
|---|---|---|
| Git、IPFS 的内容寻址 | 哈希就是名字，知道哈希就取得到内容 | 对照：Kernel 若这样按 ID 给出内容，存储就是全局可读的共享空间；见「存储不是后门」 |
| 收敛加密的确认攻击（Tahoe-LAFS 的讨论） | 密钥由内容决定时，对猜测的内容算出密文或哈希，比对即可确认 | 低熵内容的 ID 本身是信息；保管者 |
| 数据库的 GRANT、视图、行级安全；文档的分享角色与链接 | 由可信的服务集中判定；一个视图只给出一部分；链接分享知道就能用 | 保管者的判定写法。对照：链接在 Croon 里是可转交的 Port，不是口令 |
| holon；黑板系统 | 层层嵌套的整体与部分；共享的黑板 | Collective 的嵌套；保管者 |

## Definition：Interface 与组合

| 先例 | 观察 | 与设计的关系 |
|---|---|---|
| WASM Component Model 与 WIT | 组件以接口声明导入的能力，默认无权限 | Required port |
| Effect-TS Layer | 依赖编码在类型参数里，组合时检查 | Required port 与接线 |
| 代数效应与 handler（Koka、Eff、OCaml 5、Unison 的 abilities） | 签名里声明效应，handler 拦截并处理，未处理的效应是错误 | 交出到 Required port 是发起效应，实例化时的接线是装 handler，Middleware 是作为参数传进去的转发 handler |
| Lex | 效果行；按内容寻址的 AST；只追加的日志；authority derive：从声明的需要折算最小授权 | 需要从各工具的 Required port 算出 |
| 架构描述语言（Wright、ACME）；组件模型的装配 | 组件 = 接口 + 实现；连接器是一等实体，可连多端，Wright 的连接器带用 CSP 写的 glue | Interface 与 Implementation；Charter 的接线。对照：Croon 不设协议语言，复杂的连接器由 Seat 中固定的程序承担 |
| Operad / Poly（Spivak） | 层级组合是接口的组合；接线图由框、端口、线组成，嵌套是代入 | Charter：Seat 是有类型的洞 |
| MOISE+；Horling & Lesser 的组织类型学 | 组织规范拆成结构、功能、规范等维度；link 分 acquaintance、communication、authority | 成员之间的关系是接线字段的取值；三种 link 对应知道它、持有它的 Port、持有它的 Control。对照：MOISE+ 预设成员自主、可能违规，有规范与制裁；Croon 没有制裁 |
| AGR（Ferber） | agent 在 group 里扮演 role；加入、离开是动态的 | 对照：Croon 的成员固定，动态的是参与者 |
| ML 的 functor；依赖注入；LangGraph 的 create_supervisor、CrewAI 的 Crew、AutoGen 的 RoundRobinGroupChat | 按签名参数化，由组装的一方注入实现；结构与终止规则是模板 | Seat：固定的做法用 pin，允许选择的由实例化的一方注入 |
| 电子机构 | 场景与角色；每条消息都经 governor 中介 | 刚性：复杂的连接规则由 pin 的成员 Definition 承担 |
| Searle，构成性规则 | 组合主体由规则声明而存在 | Collective 由 Charter 构成 |
| 多方会话类型（Honda、Yoshida、Carbone）；类型化的 π 演算 | 全局协议投影为局部协议，投影良构则无死锁，现有实现都不支持委托；通道的类型带着通道的类型，会话通道按协议只用一次 | 对照：Croon 不设协议语言，嵌套的附带形状是它的弱形式；「只能用一次」的限定 |
| CSP（Hoare） | 迹是接口上可观察的事件序列 | Port 上的交出与到达 |
| 合同网（Contract Net） | 招标、投标、授予 | 运行中的组建属于 Cognition |
| AIRL、ATP/IR、Agint、Pipeline IR、DeepEye | 把智能体流程写成数据的中间表示。Pipeline IR 在加载时检查类型、环、悬挂端口与连通性；DeepEye 把概率性的 AgentNode 与确定性的 ToolNode 分开 | Definition 是数据，构造时检查；悬挂端口与连通性对应 Charter 构造时的接线检查 |
| SIGIL、AG-IR | 分离模型拥有的认知与代码拥有的机制；自报编译后由 harness 执行 86% 的强制步骤，数字未复现 | 对照规则与判断的分工：明确哪些步骤由固定程序执行，哪些结果交给模型决定 |
| AgentOS AIR | 加载、验证、diff、patch、影子模拟之后才确定执行 | 对照试跑：不影响真实工作地运行候选的 Definition |

## Language

| 先例 | 观察 | 与设计的关系 |
|---|---|---|
| Ingot（github.com/mathissdupont/ingot） | Agent IR 是 JSON 数据；节点用变量绑定传递数据；表达式是纯的 | Definition 是数据 |
| Harn Task-Plan IR | 窄的规划器 IR 编译成完整的工作流图 | 对照：Croon 不编译 |
| Temporal | 控制流交给宿主语言；allOf 首个失败即返回，不取消兄弟分支；重放按命令序号匹配，要求代码确定；改代码要按版本分支；TS SDK 把工作流放在确定的 V8 隔离上下文里重放 | Lang0 恢复时从头重放、在交出与取处匹配结果；并发用现成的进程池，退出时等全部分支；Language 写进 Definition，换版本就是接替 |
| AWS Step Functions | 循环靠 Choice 回跳；Parallel 一个失败即中止其余，Catch 拿不到部分结果；后来借 JSONata 写表达式 | 对照：失败带上各分支的结果；写法与表达式借现成的 |
| 内部平台效应；配置复杂度时钟 | 编排 DSL 与配置一路加功能，长成一门更差的通用语言 | Language 必须拥有的只有由求值契约推出的部分 |
| Durable Task Framework | WhenAll 等全部子任务结束后才失败，但 await 只暴露第一个异常 | 并行的失败语义 |
| van der Aalst 的工作流模式 | 控制流模式的清单 | 检查 Lang0 表达力的对照表 |
| Saga | 失败后按步补偿 | 补偿在 Library |
| Starlark | 类 Python 的写法；确定、默认无 I/O；没有 class、try、with、while 与递归；Bazel 用它确定地算出要做什么，再交给沙箱执行；成熟的实现在 Go、Rust、Java | 对照：没有采用现成的 Starlark 实现，计步、挂起、回收没有公开的入口，与 Python 的先验也差得多；算与做的分工作为 Language 的边界留下 |
| Monty（Pydantic）；Ouros | 专为运行 LLM 写的 Python 设计的纯 Rust 解释器；Monty 用 Ruff 的 parser，跑在自己的字节码 VM 上，没有 CPython 与 FFI；据记忆能在宿主函数调用处挂起并存下状态。Ouros 定位相近，成熟度不明 | 对照：Python 的子集，没有采用；挂起存成数据是 CPython 给不了的 |
| CPython 的 ast 与 symtable；RestrictedPython；pysandbox | ast 就是 CPython 自己的语法与位置；symtable 给出与 CPython 一致的作用域；RestrictedPython 把属性、下标、迭代改写成钩子调用，自述不是沙箱；pysandbox 的作者认定 CPython 在语言层关不住，放弃了 | 对照：Lang0 用自己的求值器，没有采用 CPython 作引擎，理由见 ../Lang0/Engineering.md；隔离靠每个 Instance 一个单元，语言层的限制只作纵深防御 |
| CPython 的 WASI 支持；wizer | 据记忆 3.13 起 wasm32-wasi 为 tier 2；wizer 把 wasm 模块预初始化成快照，压低启动成本 | 隔离单元的候选 |
| Erlang BEAM 的 reduction；Lua 的 debug.sethook | BEAM 给每个进程一份 reduction 预算，用完让出，计的是调用与基本操作；Lua 能按指令数挂钩回调（据报告） | Lang0 的步数按 Surface 的运算计，与宿主的指令无关 |
| FoundationDB 的 Flow；madsim、turmoil；rr；TigerBeetle 的 VOPR | 时间、随机、调度、I/O 换成可记录的、确定的源头，同一个种子复现同一次执行（据报告） | Plan 的测试策略：假的 llm 与 exec、录下再回放、重放用性质测试 |
| Scheme 的 call/cc | continuation 是一等值，能在任意点存下求值状态 | 对照：Checkpoint 要的就是这个；求值器的状态是数据，才存得下 |
| 嵌进 WASM 的 CPython、Go、OCaml、QuickJS，AssemblyScript | 据报告：CPython 慢 2–5 倍、单个模块约 40MB、与 WASI SDK 和 Wasmtime 的版本强耦合；Go 把运行时与 GC 带进模块，map 的迭代随机；OCaml 的 wasm_of_ocaml 用 WasmGC，效果要靠 CPS，自述未到生产就绪；QuickJS 约比原生 Node 慢 3.7 倍；AssemblyScript 不是完整的 TypeScript。线性内存的快照是整个运行时，不是逻辑上的 continuation | 对照：确定性靠我们规定的子集，不靠宿主语言；WASM 只作隔离的候选，见 ../Lang0/Engineering.md 的待定 |
| rustpython-parser；Ruff 的 ruff_python_parser | 公开的解析 API，AST 贴近 CPython，带位置；rustpython-parser 在 crates.io 为 0.4.0；Ruff 的是否在 crates.io 发布不明 | Lang0 解析器的候选，见 ../Lang0/Engineering.md 的待定 |
| wasmtime 的 fuel；EVM 的 gas；starlark-go 的 SetMaxExecutionSteps | 确定的计量：同样的程序与上限总在同一处停下；wasmtime 还能挂起、把控制交还宿主。EVM 调 gas 的价格要硬分叉，EIP-1884 弄坏过依赖旧价格的合约（据记忆） | Lang0 的步数。对照：fuel 数的是编译后的指令，随实现变，只作隔离单元的兜底；Lang0 按 Surface 的运算计。兜底的计量不进 Journal，就不必冻结一张计费表 |
| 证明携带代码（Necula）；DeCI；反射塔（Amin 与 Rompf 的解释器塔） | PCC：不可信的代码带证明，运行前由小的可信检查器验证。DeCI：据报告是不可信的编译器加可信的验证器，出处待补。反射塔：解释器一层套一层，每层的反射改动下一层；「门槛」一说待核验。静态成本界定：运行前算出代价的上界，计量就不必发生 | 对照：Kernel 不在运行前验证 Language。违约最坏是停下，确定性由重放分歧事后查；Kernel 也不在塔底解释什么，它守在每个 Atom 的边界上。见 ../Kernel/Language.md 的待定 |
| CPython 的 RecursionError 与 MemoryError | 深递归与对深嵌套的值做 repr、比较，都报 RecursionError | Lang0 的深度把调用与深遍历合并计数 |
| multiprocessing 的 Pool.map；concurrent.futures 的 ProcessPoolExecutor；functools.partial | 跨进程只收按名字找得到的顶层函数，lambda 与嵌套函数传不过去，参数 pickle 过去；多的参数用 partial 绑上；with 块退出时等全部任务，正在跑的取消不了；ThreadPoolExecutor 的文档写了任务互相等待的死锁 | Lang0 的并发就是它，Surface 里直接写。对照：据记忆 3.14 起 Linux 的默认启动方式不再是 fork（待核验）；Lang0 要的是 spawn，不依赖默认值 |
| LangGraph、OpenAI Agents SDK、Pydantic AI 的工具 | 普通函数就是工具，Schema 从签名与 docstring 推出；依赖放在全局，或放在不进 Schema 的第一个参数（上下文对象）里；Pydantic AI 按类型认出这个参数 | 工具从函数推出 Schema。对照：那里的工具是进程内的可信代码，依赖不代表权利；Croon 的引用按参数传或由闭包捕获，在源码里看得见 |
| FastAPI 的依赖注入；pytest 的 fixture | 按参数的类型或名字把注入的与请求的数据分开 | `main` 的参数按类型分成 Signature 的 in 与 Required port |
| TypedDict；requests 的 Response 与 `.json()`；Box、EasyDict | TypedDict 的值就是普通的 dict，类型只用来检查；requests 的响应对象用属性，`.json()` 给出的数据是 dict；Box、EasyDict 让 dict 也能用属性访问 | 值就是 dict；运行时对象用属性。对照：TypedDict 只做静态检查，Lang0 在运行时查，有成本；Box 是两种表示，没有采用 |
| 从 OpenAPI 生成的 SDK，如 OpenAI SDK | 每个方法的返回类型由它的 Schema 定，写法都是调用 | 交出就是调用，返回由 Port 的类型决定 |
| select.select | 返回的就是传进去的那些对象 | 到达的 `.port` 是传进来的 Inbox |
| Bazel 的 .bzl | 只有代码、不带权利的模块，按路径 load | 对照：Lang0 没有 load，代码 Tree 里的模块按 Python 的目录语义 import，一样不带权利；取出 `main` 的办法待定，见 ../Lang0/README.md 的待定 |
| AWS Lambda 的 context 参数 | 处理函数除了输入，另收一个运行环境的对象 | 诞生里 Tree、Seat、名册作为一个 `Birth` 参数的候选 |
| Escapement；statekit/ai；Hyperchart | 控制流是 statechart，不是模型的循环；Hyperchart 用 Harel statechart，追加式 JSONL，已完成的工作从事实重放 | 对照：Lang0 的控制流是 Python 的循环，不是显式的状态机；追加式事实加重放与 Journal 同向 |
| philip-machine；gai-harness-asm | 把 Mermaid stateDiagram 提升为可运行的 FSM | 与文档载体里 stateDiagram 可被代码取用同向 |
| WebAssembly；SGH；Flopod | 结构化控制流：Wasm 的跳转目标限于嵌套块，一次线性遍历即可验证，不会有不可约的控制流图；SGH 与 Flopod 的图与 IR 双射；Flopod 是基于结构化程序定理的最小控制流内核，超出 IR 表达力的内容降为代码活动（「入是部分的」） | 支持控制流用结构化、不用任意图加跳转；对照 Lang0 的子集：循环、with、函数，没有跳转 |
| agentgraph（kenaz-harness，Go，出处待补） | 节点类型较丰富的 Agent 图 DSL；加载时校验，循环须声明上限 | 对照：Lang0 的步数上限 |
| Conductor；Argo Workflows | Conductor 的 DO_WHILE 后置判断，条件可见迭代号与显式传入的变量，每次迭代一个 checkpoint，没有 break 原语；Argo 没有循环节点，靠展开（withItems 等）与递归加 when，全局递归上限默认 100 次模板调用 | 对照：Lang0 的键是分支里的计数器，不带迭代号；Checkpoint 连同计数器存下 |
| Ironclaw 的 subagent spawn | 以 (parent_run_id, parent_turn_id, spawn 调用序号) 作幂等键 | 与 Lang0 的键同一思路：所在位置加序号 |
| Lisp 的元循环求值器 | 据记忆、待核验：求值器可用宿主 Lisp 表达，以表达式与环境为输入；eval 与 apply 各管表达式和调用，执行仍有一个已存在的宿主起点 | 线索是求值器实现可成为数据，并区分对象程序的环境与运行器；这不自动给出不受信代码的隔离、持久执行或问责，不能由类比推出 Language 的递归形状。见 ../Kernel/Language.md 的待定 |
| Lisp 与 Smalltalk 的 image；Common Lisp 的 condition 与 restart | image 是活的运行状态，可原地修改，与保存的 source 分开；代码即数据，宏在展开时生成代码；同像性：代码与数据只有一种表示；运行时 eval；condition 的 handler 在栈展开之前运行，restart 让出错处按 handler 的选择接着走。Lisp 影响大、份额小，方言分裂 | Instance 对应 image，Definition 对应 source，Journal 是能重放到任意前缀的历史；对照：原地修改与运行时 eval 不收，见 ../Kernel/Instance.md 的「同一性」与 ../Lang0/README.md 的「拦什么」；同像性只收一半，Definition 是数据，但 Interface 与 body 分开。restart 对应 Library 的「失败时问处理者」。方言分裂对应「是否把契约写成规范」的待定 |

## Instance：Journal、重放、同一性

| 先例 | 观察 | 与设计的关系 |
|---|---|---|
| Golem Cloud | 副作用记入操作日志，故障后重放恢复；按日志位置分叉 | Journal 与重放；分叉 |
| 持久执行的 journal（Restate、Akka Persistence） | 执行的每一步记入 journal，恢复时按它重放 | Journal 的名字 |
| awflow（出处待补） | 调用 journaling 以内容 hash 为键 | 没有采用：同一内容可能出现在不同位置、结果不同，所以键由 Language 按位置给出 |
| Skuld 的 EffectLogger | 日志记 executed、discarded、started 三态；冷恢复 | started 对应 unknown；没有记录就是没发生，不需要 discarded |
| reel | 状态、副作用、能力都是按内容寻址的块；fork、commit、abort | 分叉的候选 |
| 中断副作用分类（出处待补） | safe / after_reconciliation / forbidden / unknown；不确定的副作用阻塞后续直到对账 | 对照：Croon 按出站代理的记录判断，不靠声明 |
| Cloudflare Durable Objects | 每个对象全局唯一、单线程、自带持久存储；事务按对象划，跨对象不原子 | 可变状态只有一个主人。对照：Croon 的事务单位是系统，交出与到达、撤销、Collective 的诞生在系统内原子 |
| CRDT | 几方各持一份副本，交换操作后按合并规则收敛，没有中心协调者 | 几方共同编辑，各副本仍然只有一个主人 |
| Orleans 的 grain | 持久的虚拟 actor；按 turn 逐个处理请求 | 对照：Instance 一生求值一次，状态由 body 携带 |
| Erlang/OTP 的 gen_server | 进程一生一次，body 循环 receive 再 reply；call 带上回复地址 | Instance 一生求值一次；回复地址对应附带的回话途径 |

| Erlang 的热加载；滚动更新；strangler 模式 | 新旧两版并存，旧的逐步迁走 | Kernel 不换人；派单者 |
| Kubernetes 的 Service；可升级合约的 proxy | 稳定的地址，背后的端点或实现可换；端点表归一个 controller | 地址与 Instance 两种同一性；转交者 |
| 没有管理员密钥的智能合约；The DAO 之后的硬分叉 | 没有共同根的各方靠不可变得到可信承诺；最终仍被社区推翻 | 不设可信的放弃；放弃不相对根 |

| Cloudflare Dynamic Workflows | 为运行时加载的代码做持久执行，每个租户的代码可以不同 | 与「Definition 是运行时数据」最近 |

|---|---|---|
| 对象能力模型：KeyKOS、seL4 的 c-list 与 capability derivation tree；Mark Miller 的 permission 与 authority | 权利由内核持有；转授记派生链，撤销递归；能造成的效果包括借别人的行为造成的 | Reference |

| seL4 的 CSpace；Unix 的 fd 表与语言里的文件对象 | 引用与数据分开存放；fd 号是进程表的下标，放进内存也只是数；Python 的文件对象把它包成不透明的值，但留着 fileno() | 分开的是存放，不是名字：Kernel 这一层像 fd 号，Language 这一层像文件对象。对照：引用值不留与字符串互转的口子 |
| Effekt | capability 早期是二等值，不能存进数据结构；后来加了 box，让它能当一等值用 | 全分开太紧；对照：两套名字空间没有采用 |
| petname 系统（ocap 文献） | 本地起的名字指向引用，名字只对自己有意义 | ReAct 的 petname 表 |
| caretaker、membrane（ocap 文献） | 在引用前接一层，转发并可撤销 | 保管者；撤销权 |
| Macaroons；OAuth scope | 凭证可加限制、不可放宽；第三方 caveat 要另一方判定 | 限定：派生链上每一节都要满足，加一节只会更窄，安全不靠比较器；第三方 caveat 对应保管者按规则判定 |
| Rego、Cedar、Zanzibar、OPA | 集中的授权决策点，按身份判定，默认拒绝，不跟踪派生链 | 对照：当作权利来源就是环境权利；在 Croon 里是登记者、保管者的判定写法 |
| DelegateGuard、ChainCaps | 每次效果发生时重新检查祖先链是否仍有效 | 每次交出按 c-list 解析，沿派生链合取每一节；撤销 |
| VERA；MAD（IETF 草案） | 树级联撤销会误伤共享的 agent；MAD 一次停整棵树，问责链由签名记录重建 | 对照：前提是权利挂在 agent 的身份上。Croon 按 Reference 撤销，共享者只失去被撤的那一份；撤销不等于停下 |
| KeyKOS 的 meter | 配额是能收窄的引用，由内核在消耗点强制 | 对照：全组预算在扩展里 |
| confused deputy（Hardy 1988） | 有权利的程序被请求者说动，替它滥用自己的权利 | 形状检查不保证功能正确；权利由 Reference 限定 |
| lethal trifecta（Simon Willison） | 私有数据、不可信内容、对外通道三者齐备即可外泄 | 持有意味着什么 |
| Agent libOS | 模型看得到的可供性可以演化，资源权利只经显式、可审计的运行时原语改变 | 授权只收窄；模型不是授权来源 |
| ACC；Capability Tokens；Typestate-Enforced Agent Loops；ACT | ACC：技能声明所需权限，子 Agent 的权限单调递减，每个授权决策可审计。Capability Tokens：单调衰减、有界委托深度。Typestate-Enforced Agent Loops：策略门在编译期不可跳过。ACT：WASM Component Model 之上的工具 RPC | 授权只收窄；有界委托深度对照 Library 的「委托不超过两层」 |
| CAPMAS | 语义作用域加 Macaroon，离线防篡改的委托；自报比 OAuth 令牌交换快 30 倍，未核验 | Macaroons 的同类，见上 |

| Faceted Authority Attenuation；Monotonic Narrowing | 前者把授权形式化为乘积格上的元素，委托是单调函数；后者：委托能力只衰减、不放大。均为论文，出处待补（后者在 Zenodo） | 对照：Croon 用派生链合取，不需要判断一份说明是否比另一份窄 |

## 组合

研究观察：上面的每一块都有成熟的工作；数据写成的 IR、可替换的 Language、效果靠接线、四条保证作为第一性约束，这几样合在一起，没有找到现成的实现。最接近的 Agent libOS、reel、Lex、Skuld 都是语言层的，Language 与求值模型绑定。

研究观察：另有几个与整体的划分相近。Anthropic Managed Agents（托管服务）把 Agent 虚拟化为 Brain（Claude 加 harness）、Hands（沙箱与工具）、Session（只追加的事件日志），可独立扩展与替换，对应 llm Port、exec Port、Journal。UAA：运行时内核为非确定的 AI 代理提供确定、持久的执行层，Manifest 与 Runtime 分离。Quine：LLM Agent 作为原生 POSIX 进程，递归委托靠自实例化。Nexa：不可变的树状态引擎，写时复制，O(1) 逻辑快照，对照 Tree。Springdrift：23 天单实例部署，追加式记忆、监督进程、git 支持恢复。

我们的推断：上一段的判断不变。UAA 把编排抽象成状态机，在这之上保持确定性，它的定义不可执行；Croon 的确定性在求值层，定义本身可执行。UAA 的这一点经用户确认，其余几个未逐一核对。

我们的推断：自研的必要在组合与保证，不在各块。各块里能直接采用的，优先采用；Lang0 在求值契约之后，换掉它不影响 Kernel。

我们的推断：整体实质上是一个给 LLM 进程用的操作系统内核：Instance 是持久的进程，Reference 是能力，Kernel 的 Port 是系统调用，Journal 是只追加的记录，Value 与 Tree 是按内容寻址的对象库，Definition 是程序映像加清单，Language 是跑在上面的编排语言。这几轮的结论收敛到 SwingSet 已有的结构，是好迹象，也说明这一块不该再自造。持久执行引擎（Temporal、Restate、DBOS）只作参照，不作地基：Journal 必须是唯一的记录，交出与它造成的到达要在同一个事务里跨两本 Journal 写下，建在它们上面就有两份记录。
